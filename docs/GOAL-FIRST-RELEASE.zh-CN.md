# Open RSI 首发版本：Codex Goal 任务书

日期：2026-10-23。本文供用户在主开发聊天中通过 `/goal` 引用后执行。任务范围、当前优先级和完成条件以本文件为准；现有开发记录和研究资料提供实现上下文。

2026-10-24 用户补充授权：缺少个人 API 或 GPU 资源的项目，可以保留接口/配置入口及待实测说明，稍后由用户补资源，不阻挡其余首发交付。已确认 D15 没有个人 GPU，不租用、不使用公司资源。资源缺失项必须完成当前可做的模板、输入、说明和错误提示，不能写成已经实测；其他可执行事项继续完成。下文总验收按这项资源例外执行。

## 1. 总目标

把 Open RSI / RSI-Anything 推进到可对外演示、可由其他用户安装运行、覆盖下列 15 个领域案例的首发 Demo 版本。完整交付通用循环、领域模板、真实多轮实验、可查看的产物、统一展示、安装说明和接手文档。

这是一个以演示效果和传播为主要目标的初版项目。重点是让人看到：用户给出目标，AI 实际修改产物，工具执行和评审产生反馈，系统保留较好的版本，并继续尝试。基本规则、程序指标和一个可用模型评委足以支持首轮开发。

优先把真实流程与作品做出来。工程工作优先解决正常运行、结果保存、必要的超时清理和用户上手问题。复杂评委研究、强对抗隔离、大规模统计验证和高级搜索算法列为后续增强。

展示可以选择有代表性的成功案例，同时保存该次运行完整轮次。允许停滞、失败和拒绝，不要求每轮分数上涨。模型评审分数只说明该评价下的结果；展示实际作品如何变化，不把它等同于真实业务收益。

## 2. 执行方式

用户启动 Goal 后，先检查项目和环境，形成执行计划，然后直接开展开发、实验和验证，持续推进到完成条件满足。不要停在审计、调研或写计划阶段。

在 `docs/GOAL-PROGRESS.zh-CN.md` 维护执行表，每项写清：状态、具体任务、依赖、验收条件、产物或记录路径、下一步。状态使用“待做、开发中、等待外部条件、已验收”。阶段成果可报告，但阶段完成不等于总 Goal 完成。

先做投入较小的验证，再扩大实验。技术问题主动读日志、查代码、查相关历史和官方资料，尝试最小修复。普通实现选择自行决定。确实需要账号、额外费用或素材授权时集中向用户提出，继续其他不依赖该条件的工作。

遇到权限限制遵循当前工具要求，不绕过限制。遵守用户和系统设置的预算与停止条件；预算耗尽不等于任务完成。仅当全部必需交付通过验收，才将总 Goal 标为完成；外部阻塞的项目仍算未完成，按 Goal 工具规定处理状态。

给用户的进度更新保持简短、简体中文、说人话，只讲重要结果、实际阻塞和需要决定的事。深入调查、命令入口和细节沉淀到项目文件。

## 3. 开工前恢复上下文

按需阅读：

1. `docs/DEMO-PLAN.zh-CN.md`：已有四个 Demo、实际结果和初版方向。
2. `docs/DEVLOG.zh-CN.md`、`.agents/WORKLOG.md`：开发记录与已知问题。
3. `docs/PLAN.zh-CN.md`：架构与领域扩展设计。
4. `docs/research/`：原有调研和开源组件复查。
5. `src/`、`tests/`、`examples/`：实现、测试和历史产物。
6. 仓库内适用的 `AGENTS.md` 与提交身份、隐私规则。

检查当前分支、远端、未提交修改和运行中的任务，保留已有工作。已有开发主要在 `rebuild`；当前状态必须重新核对，避免与其他聊天同时修改同一块代码。需要隔离时按现有约定处理，不丢弃未提交修改。

历史基线：代码提速与文案有完整记录；提示词优化只有部分记录；视频有模板。登录检查、进程清理和部分文档曾未提交，开工时以实际 Git 状态为准。

检查一个可用的执行助手与模型配置，以及 Python、Git、视频处理等依赖。不得使用公司内部账号、数据或基础设施完成这个个人项目。现有个人账号与已获授权的资源可继续使用；新增付费资源先说明用途与成本。

## 4. 调研要服务具体实现

沿用已有研究，对本轮实际使用的组件补查官方仓库、文档和示例。每次选型回答四个问题：解决什么具体问题、最小接法是什么、依赖与成本是什么、比当前实现多带来什么可见效果。

记录官方来源、查阅日期、选用版本及实际调用位置。区分实际使用、参考思路和候选组件。复用现有主循环，不为增加项目名称引入重复的编排或搜索系统。

先完成足以决定接法的调研，再做最小验证。遇到具体实现障碍时继续查资料，不把所有领域都研究透作为开工条件。

## 5. 通用引擎验收

| 能力 | 首版完成条件 |
|---|---|
| 任务配置 | 目标、输入素材、可改文件、执行步骤、评价方法和停止条件明确 |
| 模型调用 | 至少一套配置真实跑通，记录实际型号、调用方式和必要参数 |
| 多轮运行 | 从当前最好版本继续尝试，记录接受、拒绝、失败和停滞 |
| 外部工具 | 支持测试、训练、视频渲染和资料处理等命令 |
| 产物保存 | 初始、逐轮与最终产物有稳定路径，不因临时目录清理而丢失 |
| 中断处理 | 正常停止、超时和重新启动后能辨认已完成工作，避免无意重复昂贵步骤 |
| 资源控制 | 设置轮数、单步超时和运行时长，展示可获得的调用量或费用 |
| 导出 | 任务配置、轮次、产物、关键修改和报告能整体保存与分享 |

只抽取已出现的共用需求。领域专属逻辑先放领域包，避免为假想扩展重构整个系统。

## 6. 必须覆盖的 15 个领域案例

| 编号 | 领域与具体 Demo | 每轮改什么 | 最小验收与展示 |
|---|---|---|---|
| D01 | 工程提速：模糊搜索 | 搜索实现 | 固定基本正确性检查、速度结果、关键修改；优先复用已有完整实验 |
| D02 | 工程修复：修好小型 Python 项目 | 业务代码 | 固定测试、逐轮修复、最终可运行示例 |
| D03 | 提示词：外卖客服八分类 | `prompt.md` | 初始与最终提示词、准确率、错例、已有留出集最终结果 |
| D04 | 算法与训练：CPU 小型分类 | 参数、预处理或训练代码 | 固定划分、指标、耗时、错分变化、最终配置 |
| D05 | 自媒体文案与写作手册 | 文章及可复用手册 | 单篇多轮变化；手册用于几份简报，再用于一份新简报 |
| D06 | 视频剪辑：口播变短片 | 选段、顺序和必要参数 | 原素材、初剪、中间片段、最终成片均可播放 |
| D07 | 视频生成：简报变短视频 | 生成提示词与参数 | 有真实生成接口调用、多轮片段、要求满足情况和可播放对比 |
| D08 | 金融研报：固定资料经营分析 | 正文结构、论证与图表 | 资料来源、数字一致性、报告版本与最终成稿 |
| D09 | 量化研究：简单策略回测 | 策略规则或参数 | 固定历史数据、交易成本、回测曲线和回撤；说明历史模拟性质 |
| D10 | 文科研究：给定资料综述 | 结构、论点与证据组织 | 资料对应、引用、覆盖情况、文章前后对比 |
| D11 | 法律文本：示例合同问题梳理 | 问题清单与文本建议 | 对照预设问题及给定材料，展示遗漏和表达改善；限定示例用途 |
| D12 | 医学科普：资料转公众说明 | 信息组织与表达 | 使用明确来源材料，检查一致性与重点覆盖，展示易读性变化；限定科普用途 |
| D13 | 学习教育：讲义与练习讲解 | 讲义、例题与解释 | 固定练习上的表现、关键讲解变化、最终学习材料 |
| D14 | 生活规划：一周日程 | 时间分配和安排 | 检查冲突、覆盖与偏好，展示日程前后变化 |
| D15 | 推理加速与 GPU 算子优化 | 一个常见算子的实现及启动参数 | 数值检查、单算子多轮耗时、小型推理模块替换对照、代码变化与设备信息；按 `research/F-kernel-inference-demo.zh-CN.md` 实施 |

每个案例都要有默认输入、替换用户输入的入口、启动方法、评价说明和真实实验记录。通用引擎“理论上能配置”不算领域 Demo 完成。一个案例换标题不能算另一个领域包。

模型生成任务必须真实调用模型或工具。可以用合成数据或素材开发，但要标明来源；手工准备的输入、模板和展示布局可以使用，不能将手工编写的候选序列称为自动迭代。

D15 首例从公开 Softmax、归一化或融合计算中选一个，复用现有 RSI 主循环，参考公开的 AutoKernel、KernelBench、Triton 等项目。先优化单算子，再放进小型推理模块测整体效果；GPU 实测只在可用且已授权的个人资源上运行。缺设备时先完成可执行模板和说明，将 GPU 实验保留为待完成。

## 7. 四批实施与交付

### 第一批：已有成果与共用能力

- 整理 D01 已有代码提速证据；仅在变化导致需要重新验证时补跑。
- 完成 D03 的一次完整运行，保留原部分实验，不覆盖原记录。
- 补 D05 的文案逐轮产物与对比。
- 补齐影响上述任务的模型配置、超时处理、产物保存与导出。
- 按当前项目方式运行相关测试，实际走通启动到查看结果的路径。

交付：几个可直接查看的完整案例，以及统一结果目录约定。

### 第二批：宣传主展示

- 集中完成 D06 的真实口播剪辑，先用现有转写与 FFmpeg；需要时增加局部组件。
- 剪辑初版用剪后文字、时长和句数等评价，人工检查成片可播放性与明显剪切问题。
- 完成 D05 的写作手册迭代：固定写手根据手册为几份简报生成稿件，反馈汇总后再改手册，最后展示新简报结果。
- 同步实现统一结果浏览，展示初稿、中间版本、最好版本和每轮原因。
- 若已有兼容且授权的 GPU，同批推进 D15，把真实算子优化作为技术类主展示；否则先准备模板和运行说明，在第三批解决设备条件后实测。

交付：可播放的视频前后对比、可翻阅的文案与手册变化、可预览的展示入口。

### 第三批：其余领域

- 优先完成依赖较少的 D02、D04、D08、D10、D13、D14。
- D11、D12 采用边界清楚的示例任务和给定资料。
- 完成依赖更多的 D09、D07；账号或资源缺失时列出具体阻碍，推进其他任务。
- 完成 D15 的 GPU 多轮实验与小型推理模块对照。公开选型和来源边界见 `docs/research/F-kernel-inference-demo.zh-CN.md`。
- 各领域先做一个完整小案例，根据实际情况选择最短的现成工具接法。

交付：15 项状态与结果入口齐全；未完成项明确保留，不计入已验收。

### 第四批：产品整理

- 统一模板命名、输入说明、启动方式、输出目录和错误提示。
- 写完整中英文 README，提供最容易上手的一例。
- 完成案例集合入口、安装与个人账号配置说明、常见问题、扩展教程、开源致谢。
- 整理一段短演示及必要截图、动图或视频，宣传文字对应真实产物。
- 从新用户角度检查安装、启动、查看结果、替换输入的完整路径。
- 准备首发构建或安装产物，并检查包中包含模板与必要资源。

交付：本地可预览、可安装运行的首发候选及完整文档。对外发布、发帖、购买资源或改动主分支按用户明确授权执行。

## 8. 多轮效果的具体要求

先列出每个任务的改善空间：文案的人群、开头和结构；剪辑的开场、冗余和顺序；训练的参数与预处理；研报的数据解释、论据和风险。

先做短实验，确认反馈能产生有意义的下一步，再开展通常 5–8 轮的演示运行。已有完整实验可复用。若达到目标提前结束，保留停止原因；若模型或环境失败，先定位原因。

旗舰案例应有多个值得展示的中间版本。效果不足时检查任务、素材、反馈和模型，再建立有明确改进理由的新实验。保持一次运行内评价标准一致，调整规则或数据后另开记录。

普通案例至少完成一次真实多轮运行，得到可解释的结果。仅有基线、单轮或半途终止的记录标为部分完成。演示效果不足可以继续改进，不能靠隐藏失败或修改分数制造连续上涨。

## 9. 统一展示要求

每个案例页面或报告包含任务与输入、初始产物、逐轮修改与原因、接受或拒绝结果、最终产物、指标变化、模型与工具、时间及复现入口。

视频使用播放器；文章支持版本比较；代码显示关键改动；训练显示曲线和错例；报告展示正文图表；日程用可读视图。优先使用现有报告基础，按实际需要增加展示能力，不默认新建复杂后台。

先完成本地预览。需要部署或发布时确认目标与用户授权，按适用的发布和目录登记规则交付。未获授权的公开发布不作为擅自执行的步骤。

## 10. 文档、提交与隐私

执行期间维护当前计划、架构说明、各领域用法、开源来源、实验记录和接手说明。文件直接描述保留的实现及当前状态，清理过期结论和冲突指令。

按完整小批次保存工作；提交、推送按用户已授权范围执行，沿用个人仓库规定的匿名身份。不得带入密钥、公司信息、内部地址或本机用户名路径。不强推，不覆盖其他聊天的修改，不自动合并或发布正式版本。

非公开资料只用于理解一般问题。项目落地使用公开资料能独立支撑的方法、自行编写代码及许可证允许的公开组件；不复制、引用、改写移植内部代码、文字、配置、私有算法细节、数据、性能数字、图片或链接。不得把内部材料作为生成任务附件，也不通过换名或翻译规避边界。公开代码保留必要的版权、许可证与致谢。

最终交接应让另一台电脑、没有原对话的 Codex 或 Opus 读文档即可继续。列明实际运行命令、结果位置、可复用经验、仍存在的问题和下一项具体工作。

## 11. 总 Goal 验收

必须逐项检查：

1. D01–D15 都有实际可运行的最小案例；资源已具备的案例有真实多轮记录。按用户2026-10-24授权，缺少API/GPU资源的案例完成模板、配置入口、无资源检查与接手说明，可作为明确的待补实测项交付。D15在取得个人GPU后再补真实多轮与小型推理模块对照，不以CPU或模拟结果替代。
2. 旗舰案例有可直接比较的初始、中间和最终产物。
3. 通用引擎、模板安装与用户上手路径经过实际验证。
4. 相关测试通过，实际产物可以读取、播放或运行。
5. 统一展示、README、领域说明、开源来源、实验记录与接手材料齐全。
6. 工作按授权范围保存、提交与同步，用户能找到实际交付物。

最终用一张表列出每个案例的状态、效果、运行记录、产物与启动入口，另列真实存在的阻碍。资源例外项按上述补充授权单列为待补实测，不计入真实多轮成功数量；其余只有模板、部分实验或测试通过的项目仍未完成。除明确授权的资源例外外，仍有必需项目未完成时不得将总Goal标为完成。

## 12. Goal 使用参考

Codex 的 `/goal` 用于持续推进有完成条件的目标；暂停、恢复和清除由用户控制，预算与运行环境限制仍然生效。[OpenAI 官方说明](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)
