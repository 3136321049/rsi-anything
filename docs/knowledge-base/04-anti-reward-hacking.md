# 04 · 反奖励黑客手册 / Anti-Reward-Hacking

> **English summary:** Reward hacking happens when an optimizer raises the
> metric without improving the intended outcome. Defend with immutable
> evaluators, path allowlists, holdout tests, independent blind review,
> provenance checks, and automatic rollback on any integrity violation.

当分数成为目标，聪明的优化器可能学会“赢考试”，而不是解决问题。这不是 AI
独有的问题，却会被自动循环放大：一次漏洞可以被尝试上百次。

## 典型作弊方式

| 表面进步 | 实际发生了什么 |
|---|---|
| 测试全绿 | 删除断言、跳过失败测试、修改 fixture |
| 延迟降到 1ms | 直接返回空结果、缓存错误用户的数据 |
| 研报高分 | 关键词堆砌、隐藏给裁判的指令 |
| 引用数量翻倍 | 链接真实但不支持主张，或互相抄引 |
| 回测收益暴涨 | 偷看未来数据、只选幸存资产和有利时段 |
| 医学证据“完整” | 编造 PMID，或把观察相关性写成因果 |

Reward hacking 的信号通常是：指标突然大涨，但真实任务、边界案例或其它
指标恶化。

## 六层防线

### 1. 冻结裁判

运行前对测试、rubric、fixture、数据切分和评分脚本计算 SHA-256。每轮前后
复核。任何变化都判无效，而不是“再看看分数”。

### 2. 最小权限

`mutable_paths` 用白名单；`frozen_paths` 对 worker 只读。网络、Shell、
密钥和生产数据按需开放。将候选放在隔离 worktree 或容器中。

### 3. 隐藏与样本外评估

开发集告诉系统方向，holdout 集检验泛化。金融使用严格时间切分和样本外
窗口；写作使用候选作者看不到的事实核查与对抗问题。不可反复用 holdout
指导修改，否则它也会变成训练集。

### 4. 多指标与硬门禁

速度提升必须同时过正确性、资源和安全门禁。报告分数必须同时满足引用真实、
数字自洽和必要风险披露。门禁不能被平均分抵消。

### 5. 独立盲审

隐藏版本身份，让未参与写作的模型或人只看任务、diff、证据和结果。要求它
主动寻找“分数上涨但目标变差”的解释。高风险任务必须有人类复核。

### 6. 可审计账本与回滚

记录假设、diff、命令、输出、哈希、分数和裁决。检测到完整性问题立刻回到
上一个冠军，并保留事件证据；不要让失败候选污染错题本或基准。

## 威胁建模清单

开始循环前逐项回答：

- 候选能否读取或修改裁判、隐藏答案、时间基准或日志解析器？
- 能否通过省略输出、崩溃、超时或缓存骗取好分？
- 外部网页能否用 prompt injection 改变 Agent 指令？
- 分数是否忽略了最坏案例、少数群体、安全或长期后果？
- 事实“有引用”是否等于“引用支持该事实”？
- 谁有权修改 rubric？修改后是否重新建立基线？

## 发现作弊后

1. 停止循环，不让系统自动“修复证据”。
2. 保存候选 diff、运行日志与冻结哈希。
3. 恢复冠军，轮换可能暴露的密钥。
4. 修补 evaluator，并把这视作**新实验**重新测基线。
5. 在 lessons 中记录可泛化的攻击模式，而非隐藏事故。

最安全的 RSI 不是“永远相信分数”，而是持续问：**这个指标仍然代表我们
真正想要的结果吗？**
