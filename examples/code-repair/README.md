# D02：记账项目经过三轮修复

[English](README.en.md)

这次真实实验从固定业务测试通过 6/15 开始，三轮分别修复金额解析、账单均分、月度汇总，最终 15/15 全部通过。输入为虚构账目，不连接支付、财务或公司系统。AI 只修改 `expense.py`，测试和示例输入在整个实验中保持不变。

| 版本 | 测试通过 | 得分 | 本轮改动 |
|---|---:|---:|---|
| 初始 | 6/15 | 40 | 浮点金额、余数、退款及日期校验存在问题 |
| 第 1 轮，保留 | 9/15 | 60 | 用格式校验和整数运算解析金额，消除精度误差，拒绝非法金额 |
| 第 2 轮，保留 | 12/15 | 80 | 完整分配余数，并拒绝非法分账参数 |
| 第 3 轮，保留 | 15/15 | 100 | 校验月份和日期，按负数退款抵扣月度汇总 |

执行助手为个人 ChatGPT 账号的 Codex CLI，显式请求 `gpt-6.1-sol`、`medium` 思考强度，使用隔离配置。CLI 没有返回实际型号，因此记录中的 `actual_model` 为 `null`；不将请求型号冒充服务端确认型号。三轮均为真实模型生成，未使用手工候选。费用没有返回，不能从调用量推算实际账单。

在项目根目录可用同一入口另开实验；需要先准备自己的个人 Codex 登录。需要指定 CLI 位置时，用 `RSI_CODEX_BIN` 指向本机可执行文件。

```bash
python3 scripts/run_demo.py code-repair --model gpt-6.1-sol --rounds 3 --minutes 25 --codex-isolated
```

导出记录包含冻结测试、原始配置、每轮完整源码、修改差异、通过/失败明细和调用量。已把导出后的初始、三个候选和最终源码分别放入新的临时目录，重新执行冻结测试和 `example.py`，结果均与原账本一致。最终示例的餐饮合计为 3740 分、交通为 420 分，10000 分账单均分为 `[3334, 3333, 3333]`。这说明此固定案例得到修复，不表示已覆盖所有记账业务边界。
