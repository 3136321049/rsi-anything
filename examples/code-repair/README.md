# D02: Three rounds of fixes to an expense tracker

[简体中文](README.zh-CN.md)

This real experiment started with 6/15 fixed business tests passing. The three rounds fixed amount parsing, bill splitting and monthly summaries in turn, ending with all 15/15 passing. The input is fictional expense entries, with no connection to payment, finance or company systems. The AI changed only `expense.py`; the tests and sample input stayed the same for the whole experiment.

| Version | Tests passed | Score | Changes this round |
|---|---:|---:|---|
| Baseline | 6/15 | 40 | Problems with floating-point amounts, remainders, refunds and date validation |
| Round 1, kept | 9/15 | 60 | Parses amounts with format validation and integer arithmetic, removing precision errors and rejecting invalid amounts |
| Round 2, kept | 12/15 | 80 | Allocates the full remainder and rejects invalid split arguments |
| Round 3, kept | 15/15 | 100 | Validates months and dates, and counts refunds as negative amounts against the monthly summary |

The agent was the Codex CLI on a personal ChatGPT account, explicitly requesting `gpt-6.1-sol` with `medium` reasoning effort and an isolated configuration. The CLI didn't return the actual model, so `actual_model` is `null` in the record; the requested model isn't passed off as one the service confirmed. All three rounds were generated by a real model, with no hand-written candidates. Cost wasn't returned, and the actual bill can't be inferred from usage.

You can start another experiment from the repository root with the same entry point; you'll need your own personal Codex login first. To use a specific CLI, point `RSI_CODEX_BIN` at the executable on your machine.

```bash
python3 scripts/run_demo.py code-repair --model gpt-6.1-sol --rounds 3 --minutes 25 --codex-isolated
```

The export includes the frozen tests, the original configuration, the full source for every round, the diffs, pass/fail details and usage. The exported starting, three candidate and final sources were each placed in a new temporary folder, and the frozen tests and `example.py` were run again; every result matched the original ledger. In the final example, `餐饮` (dining) totals 3740 cents and `交通` (transport) 420 cents, and a 10000-cent bill splits as `[3334, 3333, 3333]`. This shows that this fixed case was repaired, not that every expense-tracking edge case is covered.
